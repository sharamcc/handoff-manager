# UPDATE：增量维护

读取交接入口及本轮变化涉及的权威章节，根据实际操作、差异、验证结果与用户决定识别增量。计划不是成果，他人的未提交改动不计为本轮完成；缺少前次基线时只更新有证据的变化。

1. 列出变化及来源；需要确定落点时读 [结构规范](DOCUMENT_STRUCTURE.md)。
2. 按已有任务/决定 ID 或语义键（主题、范围、环境、版本）更新对应权威条目，不按运行时间新建 ID。任务状态须有验收依据，保留阻塞和待核实项。
3. 入口保留当前短述与索引。移出失效细节前确认唯一历史依据可追溯；缺少恢复记录时遵循 [迁移流程](MIGRATION_WORKFLOW.md) 的恢复要求。大规模重组改用 MIGRATE，检查已有授权是否涵盖。
4. 对照 [校验清单](VALIDATION_CHECKLIST.md) 检查要求、任务、引用和文档差异，报告真实变更；不无条件追加日志。

同一事实基线与输入重复运行应保持文档字节不变：沿用排序和 ID，不增加重复章节、任务、决策或快照，不仅因运行时间变化刷新时间戳。没有变化时报告“无交接内容变化”；新核验结果可更新证据，但不算新的开发进展。

人工决定的修改遵循 SKILL.md 的授权与替代链规则；无授权的提案只记录为建议或阻塞，继续无争议的维护。已授权迁移可移动要求而不改变原义，不因此重写整个受保护文档。
