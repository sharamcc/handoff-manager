# MIGRATE：可恢复迁移

## 1. 验证恢复点

列出拟改文档，按 SKILL.md 的权限与敏感信息规则检查。恢复点必须覆盖当前待迁移文件的**准确字节**：

- 已有 Git 对象：记录提交、路径和内容哈希，读回并与当前文件比较。HEAD 不自动保护未提交或未跟踪内容。
- 无匹配历史：对确认无秘密的原文制作快照，按内容哈希复用已有快照，读回核对一致；不为此自动提交。
- 含秘密：只使用可验证的受保护恢复机制；脱敏摘要不能代替原件。机制缺失时停止该文档写入。

记录恢复定位及验证结果后才可覆盖入口；不在真实工作区执行恢复覆盖或重置演练。

## 2. 完整盘点与映射

大文件先统计大小、标题和章节范围，再分段读完全文，包括标题前文本、列表、表格、附录和注释；记录已读范围，避免输出截断造成遗漏。

复用或创建本次迁移映射：

| 原文定位 | 类型/条目 ID | 目标文件及章节/ID | 处理方式 | 证据/未决项 |
| --- | --- | --- | --- | --- |
| 原始哈希、章节、行范围 | 要求/任务/决策/经验/版本等 | 可定位的新来源 | 保留/去重引用/归档/待核实 | 授权、证据或冲突 |

每个原始章节都须有去向；相同标题用原始行范围区分，定位固定在恢复点。人工约束、未完成任务、关键决策和失败经验逐项核对，不能以“全部归档”代替活跃信息提取。去重必须指向保留条目。

## 3. 分层并核验

按 [结构规范](DOCUMENT_STRUCTURE.md) 复用权威文档；已有来源冲突时不另造一份。依证据核验需求、实现、任务、决定和版本状态，无法核验则保留待核实。任务完成须有验收证据，旧决定失效须有替代依据；保持要求中的阈值、禁止条件和环境不变。

先写目标文档和映射，验证引用后，再按 [模板](HANDOFF_TEMPLATE.md) 替换入口。步骤失败时保留可恢复原件，报告已写/未写范围，不自动删除产物或用户改动。

## 4. 验收

按 [校验清单](VALIDATION_CHECKLIST.md) 对照原文与新文档，确认关键条目保留、全量映射、链接可达和范围合规。使用文件清单与差异核对；无 Git 时用内容哈希。按 SKILL.md 交付要求报告，体积目标未达成时说明原因。
