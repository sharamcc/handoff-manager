# MIGRATE：可恢复的一次性迁移

用于用户明确要求落盘整理现有交接。先读 [结构规范](DOCUMENT_STRUCTURE.md)，仅在生成入口时读 [模板](HANDOFF_TEMPLATE.md)，最后读 [校验清单](VALIDATION_CHECKLIST.md) 的迁移验收部分。

## 1. 确认范围与恢复机制

读取仓库规则、现有文档职责和工作区状态，列出拟改文档。保留不属于本轮的改动，不自动提交或清理。先在内容输出/归档前检查敏感信息，只显示脱敏位置。

恢复机制必须覆盖**当前待迁移文件的准确字节**：

- 优先使用已有 Git 对象：验证记录的提交和路径能读回，与当前文件一致，并记录对象及内容哈希。仅“仓库用了 Git”、已有 HEAD 或有远端不够；未提交/未跟踪内容并不受 HEAD 保护。
- 没有匹配的已有历史时，对已检查无秘密的当前文档制作本次迁移的原始快照；用内容哈希识别已存在快照，避免重复，验证读回哈希一致。非 Git 项目也采用此方式。不要为制造恢复点擅自 commit。
- 有秘密时不向普通归档、日志或报告复制；脱敏摘要不能代替准确原件备份。已有受保护恢复机制可验证则使用；否则停止受影响文档的写入，报告缺口，等待用户提供或授权合适方案。不得擅自改历史或“先覆盖再说”。

记录恢复定位与验证结果后才能替换入口。通过读取并核对恢复内容证明可恢复，不在真实工作区执行 reset 或覆盖恢复演练。

## 2. 全量盘点与逐项映射

大文件先统计字节、行、标题及章节范围，再逐段覆盖完整内容（含标题前文本、列表、表格、附录、注释）。不要只读开头和结尾。记录哪些区段已读，防止截断导致遗漏。

建立迁移映射，复用现有迁移记录；没有时在合适的历史文档中创建一个本次映射。至少包括：

| 原文定位 | 信息类型/关键条目 ID | 目标文件及章节/ID | 处理方式 | 证据/未决项 |
| --- | --- | --- | --- | --- |
| 原始内容哈希、章节、行范围 | 人工要求/任务/决策/经验/版本等 | 可定位的新来源 | 原义保留/去重引用/历史归档/待核实 | 授权出处、实现证据或冲突 |

相同标题用原始行范围区分。每个原始章节都必须有去向；人工约束、未完成任务、关键决策、失败经验逐项核对，不能只用“全部归档”代替活跃信息提取。去重需指向保留的条目，不是无依据删除。原始定位固定在快照/提交，不引用修改后漂移的旧行号。

## 3. 分层与事实核验

提取有效需求、架构/业务规则、当前实现、全部未完成任务、决策演变、已验证经验、版本及测试证据。复用权威文档并按最小范围编辑；有多份“权威”文档时先明确冲突，不复制出第三份。

按证据类型核验事实。遵守宿主要求选用图谱/源码、Git、已有测试或获准的无副作用验证；不能核验时保留待核实。完成任务须有对应验收证据，不能只因后文写“完成”就移除。旧方案只有具备替代依据才标记已被替代；待确认的 AI 建议仍是建议。

保留人工要求原义及出处；重写不得改变禁止条件、阈值、适用环境等。发现与代码不符时建立差异任务，不改要求。必要的人工决策变更遵循 [更新策略](UPDATE_POLICY.md) 的授权规则。

## 4. 生成入口并验收

先写目标知识及映射，验证链接，再按模板替换 HANDOFF.md。单个步骤失败时保留可恢复原件并报告已写/未写范围，不把部分迁移说成成功，不自动删除生成文件或用户改动。

按校验清单逐项确认：关键约束与未完成任务全保留、所有原始章节有去向、证据可追溯、链接有效、入口可用、变更限于授权文档。检查写入前后的文档差异与文件清单；非 Git 项目用文件清单和内容哈希。不以自动化结构检查代替人工语义对照。

输出前后体积、token 估算方法、恢复定位、映射路径、实际改动、未核实项。若未达到 token 目标说明原因；不要丢信息换取数字达标。原始恢复记录和旧文档不自动删除，提交/推送也不属于迁移动作。
