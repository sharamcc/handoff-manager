# 精简交接模板

只在创建或重组入口时读取。沿用项目语言与现有字段；以下尖括号是填写说明，不应原样留在交付文件中。不存在 Git、版本或证据时写“不适用”或“待核实”，不编造。

```markdown
# <项目名> — 当前交接

目标：<当前目标与范围>
基线：<分支/分离 HEAD；完整或可唯一解析的提交；工作区是否有未提交变更>
版本：<声明版本、标签对应提交；部署环境及版本另列，未核实则明确>
最后核验：<带时区的时间；核验的代码/文档/测试/部署范围及未覆盖项>

## 当前状态
- 最近完成：<关键交付、证据链接；区分已开发/已测试/已灰度/已发布>
- 未完成：<稳定任务 ID、状态、权威任务清单链接>
- 最高优先级：<任务 ID 与可操作的一步>

## 阻塞与人工事项
- <阻塞原因、解除条件；需要人工裁决的具体冲突及来源>

## 必须遵守
- <关键人工约束的准确短述；权威来源链接或决定 ID>
- <相关安全边界/禁止操作；不要只给一个无说明的链接>

## 下一步与验收
1. <操作、依赖、可观察的成功标准；需要额外授权时标明>

## 按需阅读
- 当前实现与证据：<链接>
- 待办与阻塞：<链接>
- 架构/业务约束/决策：<仅相关链接>
- 历史与迁移映射：<可定位的链接、Git 对象或受保护恢复位置>
```

链接以当前文档所在目录解析，优先仓库相对路径与稳定标题/ID。Git 追溯需记录仓库、提交、路径及旧章节/行号；外部证据需说明访问限制。不要把本机绝对路径当作所有人的通用链接。

预算超出时先移出日志、实现细节、版本清单和已解决事件；保留必要约束、未完成任务入口和重大冲突。多个任务可链接到清单，但不能让唯一未完成任务因“精简”消失。核验时间仅在确实核验后更新；没有事实变化的重复 UPDATE 不为刷新时间而重写。
