# 文档分层与权威来源

先检查现有文档职责，再安排信息落点。下表是候选位置，不是必建清单；小项目可复用同一文档的章节，无内容不建空文件。

| 职责 | 候选位置 | 内容 |
| --- | --- | --- |
| 项目规则 | AGENTS.md 或现有规则文件 | 操作规范，非普通交接更新对象 |
| 当前入口 | HANDOFF.md | 目标、限制、状态、下一步、索引 |
| 实现状态 | docs/PROJECT_STATE.md | 功能、证据、环境、核验范围 |
| 任务 | docs/TASKS.md | ID、优先级、状态、依赖、阻塞、验收 |
| 架构 | docs/ARCHITECTURE.md | 模块关系、源码定位、未实现设计 |
| 业务要求 | docs/BUSINESS_RULES.md | 有效口径、人工约束及确认出处 |
| 运维 | docs/OPERATIONS.md | 部署、备份、恢复及适用环境 |
| 技术经验 | docs/LESSONS.md | 失败原因、验证依据、适用条件 |
| 决策 | 现有 ADR 或 docs/decisions/ | 状态、原因、影响、来源、替代关系 |
| 版本历史 | CHANGELOG 或 docs/releases/ | 版本详情、测试与发布证据 |
| 原始记录 | Git 历史或 docs/archive/ | 可恢复原件与迁移映射 |

沿用已有 ID；重要条目保留准确陈述、状态、来源、适用时期/环境及核验范围。来源可为可定位的用户决定、受控文档、提交与路径、测试或部署记录，不虚构确认人或消息 ID。

其他文档只保留必要短述和链接。快照标为历史证据，不与当前权威来源竞争。相似内容仅在语义、范围、时期和环境一致时合并；不同版本的失败经验可能包含新的适用条件，不能按字符串相似度删除。

要求与实现冲突时分别保留，并建立差异任务；未证实的新状态标为待核实。不要用多轮压缩摘要替代唯一原始依据。
