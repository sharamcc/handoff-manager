# 长期知识分层与权威来源

先检查现有 README、CHANGELOG、ADR、任务清单、运维文档、Memory 的职责与有效性，再确定路由。下表是逻辑职责及候选位置，不是必须创建的文件列表。小项目可以复用一个现有文档的不同章节；没有相关知识就不建空文件。

| 职责 | 候选位置 | 内容边界 |
| --- | --- | --- |
| Agent 规则 | AGENTS.md | 仓库操作规范；无明确授权不改 |
| 当前入口 | HANDOFF.md | 目标、限制、近期状态、下一步、索引 |
| 实现状态 | docs/PROJECT_STATE.md | 功能、证据、环境、核验范围；区别开发/测试/部署 |
| 任务 | docs/TASKS.md | 稳定 ID、优先级、状态、依赖、阻塞、验收条件 |
| 架构 | docs/ARCHITECTURE.md | 当前模块关系与源码定位；未实现设计明确标记 |
| 业务要求 | docs/BUSINESS_RULES.md | 有效口径、人工约束、确认出处 |
| 运维 | docs/OPERATIONS.md | 部署、备份、恢复步骤与适用环境；不存凭据 |
| 技术经验 | docs/LESSONS.md | 问题、失败原因、验证依据、适用条件、防错措施 |
| 决策演变 | docs/decisions/ 或现有 ADR | 决定、状态、原因、影响、来源、替代关系 |
| 历史版本 | docs/releases/ 或 CHANGELOG | 版本详情、测试/发布证据；声明发布不等于已证实 |
| 原始记录 | Git 历史或 docs/archive/ | 可恢复原始交接与迁移映射；不反复生成同状态快照 |

## 信息条目

对影响后续行为的条目保存足够的证据关系：稳定 ID（沿用已有 ID）、类型、准确陈述、状态、来源位置、适用时期/环境、核验时间/范围。来源可以是用户消息定位、受控需求文档、提交与路径、测试结果、部署记录；不要虚构消息 ID 或确认人。

一个事实选定唯一权威来源，其他位置只放必要短述与链接。历史原件和迁移前快照是“历史证据”，必须标记时间，不能与当前权威文档竞争。决策可以是 proposed / accepted / superseded / rejected；被替代的决定保留原义、替代 ID 与授权出处。任务可为待办/进行中/阻塞/已完成，缺乏完成证据时保留待核实状态。

## 冲突的归属

人工“必须使用 A”与代码“实际使用 B”不是靠选较新文件就能消解的重复。业务要求保留 A，状态文档记录 B，任务清单记录实现差异。旧记录“未上线”和新记录“已上线”先区分版本、时间和环境，再查部署依据；未证实的新说法保留为历史声明/待核实。

相似文本只有在语义、范围、时期和环境一致时才合并。不同版本的重复失败可能包含新的适用条件，不能仅按字符串相似度删除。不要将一轮轮压缩摘要作为唯一事实来源。
